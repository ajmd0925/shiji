# ChatGPT 原生提醒验证

## 验证目的

确认个人任务助手能否使用 ChatGPT 原生任务和通知，而不是只在聊天中口头承诺提醒。

## 本次实际测试

- 日期：2026-11-17。
- 时区：Asia/Shanghai。
- 测试账号：由用户自行登录的 ChatGPT 网页账号；不保存账号、凭据或登录状态。
- 测试会话：用户账号内的原生提醒测试聊天（不公开私人会话标识）。
- 任务名称：提醒通知链路测试。
- 计划时间：2026-11-17 11:32（北京时间）。
- 类型：一次性任务。
- 提醒内容：提醒通知链路测试：这是个人任务助手的首次验证提醒。

## 已观察到的结果

- ChatGPT 返回原生任务卡片。
- 打开任务详情后，显示状态“已开启”。
- 运行位置为“云端”。
- 任务详情中的日期、时间、时区分别为 2026-11-17、11:32、Asia/Shanghai。
- 后续界面中，任务卡片显示“Completed”，聊天出现预定提醒原文；未点击“立即运行”。
- ChatGPT 的“定时任务”列表显示本任务“已完成 · 上次运行：今天”。
- “设置 → 通知 → 任务”显示“推送、电子邮件”；仅检查现状，未修改通知配置。
- 用户随后明确确认已收到第一条 ChatGPT 通知；该确认不证明通知准时到达。
- 观察完成状态前，执行环境时钟最近一次读数为 2026-11-17 03:30:22 UTC（北京时间 11:30:22）。这早于计划时间；因此本次观察不能证明准时执行，需要继续核对实际执行时间，避免将“已完成”视为“按时完成”。

## 尚待验证

- 实际执行时间是否与计划时间一致（界面已经出现完成状态和提醒消息，但出现时间需要核对）。
- 自定义插件保存业务任务后，能否在同一轮对话中创建原生提醒。
- 创建、修改或取消原生提醒后，如何与业务系统中的状态保持一致。

## 当前结论与下一步

已实测证实：当前用户账号可以从 ChatGPT 网页创建云端一次性提醒，自动执行后用户能收到邮件通知，且 ChatGPT 聊天中出现提醒。不能把邮件送达或聊天消息视为设备系统推送已送达。

尚未证实：自定义插件保存业务任务后，能否在同一轮对话中创建原生任务并得到可靠的创建结果。下一阶段应优先验证该最小集成，再开发完整业务界面；不得把这次原生功能测试称为自定义插件已接入。

## 实现约束

“业务任务已保存”“ChatGPT 提醒已创建”“提醒已执行”“用户已收到推送”是不同结果，不得混用。

只在原生任务工具或界面确认创建成功后，才能向用户报告提醒已安排。没有创建权限或创建失败时，需要保留任务并明确报告提醒未安排。

本次测试使用网页聊天的原生任务功能；尚未构建、安装或验证自定义插件。当前开发会话中的 Codex 本地自动化工具不能作为 ChatGPT 云端推送已打通的证据。
